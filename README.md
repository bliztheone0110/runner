# Momentum — бесконечный коридор на Three.js

Игра от первого лица: процедурный коридор, WASD, ручные прыжки, распрыжка через W + плавный поворот мыши и рокет-джамп.

Правила работы для coding-агентов находятся в [AGENTS.md](AGENTS.md): ограничения команд, архитектурные требования, редактирование интерфейса и освобождение ресурсов.

## Запуск

Требуется Node.js 22.12+.

```sh
npm install
npm run dev
```

Откройте адрес Vite в браузере и нажмите **Начать**. WASD — движение, мышь — обзор, Space — один прыжок, ЛКМ — ракета, R — возврат к контрольной точке, Escape — пауза. Удержание пробела не включает автопрыжки. Для цепочки нажимайте пробел непосредственно перед приземлением (буфер 100 мс).

Перед начальным меню при каждой загрузке страницы показываются `public/assets/images/intro1.png`, `intro2.png` и `intro3.png`. Кнопка **Далее** переключает изображения плавным одновременным затуханием и появлением за 200 мс и после третьего открывает меню. Во время перехода и загрузки кнопка недоступна; пока следующее изображение загружается, предыдущее остаётся на экране. При ошибке можно продолжить. С настройкой `prefers-reduced-motion` изображения переключаются мгновенно. Изображения сохраняют пропорции и помещаются целиком в экран. Игра и аудиосистема создаются только после завершения вступления. Пауза, возрождение и смена режима вступление не повторяют.

## Бесконечный уровень

Участки длиной 48 м образуют коридор шириной и высотой 12 м с потолком. Первые три участка знакомят с бегом, невысоким блоком и обычной пропастью. Затем чередуются безопасные площадки, блоки 0,8–1,2 м, пропасти 2–3 м, сложные блоки 3 м и пропасти 6,5–8 м. Примерно на каждом пятом прямом участке после вступления может появиться пандус на верхний уровень с уклоном 45°. Его подъём равен 70% теоретической высоты рокетджампа; последующие участки продолжаются на достигнутой высоте. На наклонной грани гравитация ускоряет игрока вниз по рампе, а движение вверх может противодействовать этому ускорению. Если игрок заканчивает подъём со скоростью не ниже `settings.ramps.takeoffSpeedThreshold`, он вылетает с верхнего края под углом рампы, сохраняя скорость движения по наклону. На верхней площадке скатывание не действует. Для сложных препятствий используйте разгон или ракету. Перед препятствием и после него остаётся безопасное пространство; сложные варианты не идут подряд.

Повороты на 90° объединены в пары: после бокового обхода маршрут снова направлен вперёд. Контрольная точка отмечена полупрозрачной зелёной стеной в начале каждого третьего участка. Смерть, R и падение ниже −12 м возвращают игрока к последней достигнутой точке с полным здоровьем и без накопленного импульса. Направление взгляда также восстанавливается. HUD показывает максимальную пройденную дистанцию за сессию и номер точки. Можно остановиться и восстановить здоровье.

`CorridorGenerator` использует seed и компактное сохраняемое состояние. При возрождении из снимка генерируется тот же дальнейший маршрут. В игре seed выбирается при загрузке страницы; повторный запуск с тем же seed через конструктор генератора воспроизводит уровень. В памяти остаются текущий участок, шесть впереди и два позади (до девяти). Стена у входа в самый старый участок закрывает обратный путь; удалённые участки освобождают меши и коллайдеры. Геометрия и материалы общие для всего мира. Стены и блоки используют `public/assets/textures/wall_rock.png`. Текстура каждого элемента пола в коридоре и тренировочной комнате содержит оба рисунка: `floor_stone_pattern.png` встречается чаще, а `floor_stone_pattern_depth.png` занимает две ячейки из шестнадцати в повторяющемся узоре. Второй файл используется как обычная цветная текстура без карты рельефа.

При удалении от локального начала координат более чем на 1024 м мир переносится ближе к игроку. Смещаются также предыдущее положение игрока, ракеты, эффекты и пространственные звуки; логическая дистанция сохраняется. Параметры находятся в `settings.corridor`.

## Таймер до контрольной точки

В стандартном режиме на достижение следующей контрольной точки отводится 15 секунд активной симуляции. Каждая достигнутая точка запускает новый отсчёт: лимит уменьшается на 0,5 секунды до 10, затем на 0,25 секунды до нуля. Это время на путь между контрольными точками, то есть на три участка коридора. В тренировке таймер скрыт и не работает.

При истечении времени игра останавливается, освобождается курсор и появляется окно **Время вышло!** с количеством пройденных чекпоинтов и кнопкой **Начать сначала**. Начальная точка в этот счёт не входит. `timer_end.mp3` воспроизводится один раз при открытии окна. Кнопка запускает новый коридор с новым seed, полным здоровьем и начальным лимитом 15 секунд. Пауза останавливает таймер. Смерть, падение и R возвращают игрока к точке, но не сбрасывают оставшееся время. Новый отсчёт с лимитом текущего чекпоинта начинается при достижении следующего чекпоинта; смена режима и новый забег сбрасывают таймер. Параметры находятся в `settings.checkpointTimer`; логика — в независимой фиче `features/timer`, звук обрабатывается через событие `timer.expired`.

## Тренировка и выбор режима

На стартовом экране и в меню паузы доступен выбор **Бесконечный коридор / Тренировка**. Выбор применяется при нажатии кнопки запуска. Продолжение выбранного режима сохраняет прогресс; смена режима начинает его заново и очищает скорость, статистику движения, здоровье, ракеты, эффекты и ввод. Возврат в коридор создаёт новый seed. Громкость и отключение звука сохраняются, `prepare` повторно не звучит.

Тренировка — пустая квадратная комната 80×80 м с разметкой пола, стенами высотой 32 м, без потолка и препятствий. Игрок появляется в центре. Доступны обычные прыжки, распрыжка, ракеты и восстановление здоровья. R и смерть возвращают в центр; при падении за пределы комнаты действуют пороги −2 м для звука и −12 м для возрождения. Дистанция и контрольные точки в HUD скрыты. Размеры и шаг разметки находятся в `settings.training`.

`GameWorld` задаёт общий контракт мира, а `app/WorldSession` предоставляет стабильную зависимость системам движения, оружия и возрождения. Он заменяет мир и освобождает его ресурсы. `TrainingWorld` хранит один статический участок, `WorldStreamSystem` управляет окном процедурного коридора. Новые режимы подключаются через фабрику мира в `app/Game`.

## Рокет-джамп и здоровье

Посмотрите под ноги и нажмите ЛКМ: ракета взорвётся об пол и добавит импульс вверх. Совместите выстрел с прыжком для большей высоты; взрыв сбоку позволяет получить дополнительный горизонтальный разгон. Импульс складывается с накопленной скоростью распрыжки.

Ракета летит по направлению камеры со скоростью 40 м/с, взрывается при первом столкновении и исчезает без взрыва через 5 с. Один клик — один выстрел, минимальный интервал — 0,4 с, боезапас не ограничен. Взрыв действует в радиусе 5 м, добавляет до 16 м/с и наносит до 30 HP урона. Урон и импульс линейно уменьшаются по расстоянию до тела игрока; препятствия блокируют воздействие.

Игрок начинает со 100 HP и сразу восстанавливает 5 HP/с. При нуле HP происходит автоматическое возрождение. Смерть и R сбрасывают здоровье, движение, статистику движения, ракеты, эффекты и очередь выстрелов. Пауза останавливает симуляцию, генерацию, регенерацию и эффекты. Параметры находятся в секциях `weapons`, `health` и `corridor` общего конфига.

```sh
npm test
npm run typecheck
```

Production-сборку (`npm run build`) запускать только по отдельной команде пользователя.

Это доступная механика с бонусом за поворот камеры при W. Все коэффициенты находятся в `src/config/settings.ts`. Обычный бег — 6 м/с, поворот на земле повышает целевую скорость до 7,5 м/с, в воздухе поворот даёт до 3 м/с². Прыжок сохраняет горизонтальную скорость. Количество накопленного импульса не ограничено.

Если после приземления не выполнить следующий прыжок сразу, накопленная скорость плавно снижается до базовых 6 м/с за 0,5 секунды независимо от величины разгона. Повороты камеры во время этого торможения не продлевают сброс. Буферизированный прыжок и прыжок на первом наземном шаге сохраняют скорость; без клавиш движения персонаж продолжает тормозить до остановки. Длительность задаётся `movement.landingSpeedResetDuration`.

## Звуки

Файлы из `public/assets/audio/` загружаются и декодируются один раз. При обычном прыжке с равной вероятностью звучит `jump.mp3` или `jump2.mp3`; взрывной подброс звук прыжка не вызывает. Выстрел использует `rocket_fire.mp3`, пространственный взрыв — `rocket-explosion.mp3`. `prepare.mp3` воспроизводится только при первом успешном старте игры, а `respawn.mp3` — при смерти, R и возвращении после падения. `falling.mp3` звучит один раз при падении ниже −2 м; успешное приземление или возрождение завершает эпизод падения.

Громкость по умолчанию — 50%. Ползунок и «Без звука» доступны на стартовом экране и в паузе; выбор сохраняется до перезагрузки страницы. Нажатие «Начать/Продолжить» активирует Web Audio одновременно с запросом захвата курсора. Пауза останавливает текущие звуки; они не продолжаются после возврата. Если отдельный MP3 не загрузился, игра продолжает работать. Если `prepare` ещё загружается при старте, он звучит после загрузки во время активной игры; другие запоздавшие эффекты пропускаются.

`GameEvents` собирает типизированные события симуляции. `AudioSystem` обрабатывает их один раз после движения, оружия и здоровья, `BrowserAudioOutput` владеет аудиоконтекстом, кешем буферов и источниками, а `AudioListenerSystem` обновляет позицию и направление слушателя по камере. Игровая логика не импортирует браузерные API. Параметры файлов, громкости эффектов и пространственного затухания находятся в `settings.audio`.

Для отдельного прослушивания без захвата курсора откройте `/tests/audio-preview.html` на dev-сервере: кнопки используют тот же аудиомодуль и позволяют проверить прыжки, выстрел, пространственные взрывы и возрождение.

## Стиль кода и линтеры

Prettier форматирует TypeScript, CSS, HTML тестовых страниц и конфиги: отступ 2 пробела, ориентир длины строки 100 символов, одинарные кавычки, точки с запятой и завершающие запятые. Отдельные операции размещаются на разных строках, а CSS-свойства — по одному на строку. Большие HTML-шаблоны сохраняют читаемое многострочное оформление.

```sh
npm run format
npm run format:check
npm run lint
npm run typecheck
```

`format` изменяет файлы, `format:check` только проверяет их. Команда `lint` последовательно запускает ESLint, Stylelint и `format:check`. Ресурсы, зависимости, сборка и установленные skills исключены из форматирования. Конфиги: `.prettierrc.json`, `eslint.config.js`, `stylelint.config.js`.

ESLint требует фигурные скобки, отдельные объявления переменных, строгие сравнения и типовые импорты; запрещает вложенные тернарные выражения и небезопасные утверждения `!`. В модулях игровой логики запрещены зависимости от DOM, сборки приложения, UI и rendering; представления камеры и оружия исключены из этого ограничения. Stylelint проверяет CSS и порядок специфичности селекторов. Обязательные DOM-элементы ищутся через `requireElement()` с сообщением об отсутствующем селекторе. У необязательных элементов нужно проверять `null`.

Если Stylelint на Windows сообщает `No rules found within configuration`, учитывайте ограничение загрузчика файлов в песочнице; это не повод отключать правила. Сборка по-прежнему запускается только по отдельной команде пользователя.

## Архитектура модулей

`app/Game` — единственное место сборки зависимостей. `core/GameLoop` вызывает физику с шагом 1/120 с, затем отображение с коэффициентом интерполяции. За кадр выполняется максимум восемь шагов; время сверх лимита отбрасывается, чтобы после задержек не возникали долгие догоняющие обновления.

| Модуль | Ответственность |
| --- | --- |
| `core` | Контракты, векторы и жизненный цикл систем |
| `input` | События браузера, буфер клавиш и распределение движения мыши |
| `audio` | Загрузка аудио, воспроизведение, пространственное звучание и жизненный цикл источников |
| `physics` | Интерфейс мира столкновений и непрерывная проверка движения |
| `features/player` | Состояние, механика движения и камера игрока |
| `features/weapons` | Ракеты, взрывное воздействие и независимое отображение |
| `features/health` | Здоровье, урон и регенерация |
| `world` | Генератор маршрута, окно активных участков, контрольные точки и общие ресурсы отображения |
| `rendering` | Three.js renderer, освещение и изменение размера |
| `ui` | DOM-интерфейс, запуск, пауза и телеметрия |
| `config` | Привязки клавиш и коэффициенты механики |

Правила расширения:

- Передавайте зависимости явно через конструкторы. `core` не импортирует игровые фичи; фичи не импортируют `app`.
- `InputSystem` считывает ввод один раз за физический шаг. Все фичи читают один `snapshot`; не вызывайте `InputState.consume()` из других фич.
- Для нового звукового события расширьте тип `GameEvent`, отправьте событие через внедрённый `EventSink` и добавьте его обработку в `AudioSystem`. Встроенные события обрабатываются после симуляции, до отображения.
- Порядок симуляции: ввод → подготовка мира → ручной сброс → движение → обновление участков/контрольной точки/координат → оружие/взрывы → падение → здоровье/возрождение → звуковые события. `RespawnSystem` получает точку появления через `SpawnProvider` и координирует полный сброс.
- Для внешних толчков используйте `MovementController.applyImpulse()`. Для снарядов и перекрытия взрывов используйте `CollisionWorld.traceSegment()`; он возвращает первую точку контакта с поверхностью, нормаль и долю пройденного пути.
- Физическое состояние — обычные данные. Контроллер движения не знает о DOM или объектах Three.js; камера и HUD только читают состояние.
- Используйте `fixedUpdate(dt)` для игровой симуляции и `update(dt, alpha)` для представления. Оба метода опциональны. Игровые таймеры считают время симуляции.
- Возвращайте `dispose()` для освобождения событий, моделей, материалов и геометрии. Системы освобождаются в обратном порядке регистрации.
- Не создавайте новый игровой цикл внутри фичи. Добавляйте системные модули в список `GameLoop` в `app/Game.ts`.
- Уровень задаётся `LevelDefinition`: точка появления и коробки. Коробки создают одновременно меши и коллайдеры. Для другого типа геометрии расширяйте контракт мира столкновений.
- `StaticCollisionWorld.setChunk()` и `removeChunk()` управляют коллайдерами по владельцу. Новый шаблон добавляйте в генератор данных; `ChunkRenderer` и `WorldStreamSystem` управляют его представлением и сроком жизни. Декоративные коробки помечайте `collidable: false`.

### Пример новой механики

Например, создайте `src/features/abilities/AbilitySystem.ts`:

```ts
import type { GameSystem } from '../../core/types';
import type { PlayerState } from '../player/PlayerState';

export class AbilitySystem implements GameSystem {
  constructor(private readonly player: PlayerState) {}

  fixedUpdate(dt: number): void {
    // Пример таймера способности, который обновляется только в симуляции.
    this.cooldown = Math.max(0, this.cooldown - dt);
    if (this.player.grounded) {
      // Здесь можно обработать запрос способности на земле.
    }
  }

  dispose(): void {
    // Освобождение ресурсов, которыми владеет эта система.
  }

  private cooldown = 0;
}
```

Добавьте запрос способности в контракт ввода, передайте `InputSystem` в новую систему, создайте её в `app/Game.ts` и зарегистрируйте после системы игрока. Визуальные эффекты оформите отдельным модулем представления с `update()`. Аналогично подключаются противники, интерактивные объекты и звук.

## Проверки и ограничения первого этапа

Автоматические тесты проверяют движение, распрыжку, ракеты, звуки и поведение при разной частоте кадров. Проверки коридора включают воспроизводимость seed, стыки и отсутствие пересечений, прохождение каждого типа шаблона существующей физикой, сохранение точки, удаление участков и перенос координат. Длительный прогон из 3000 участков контролирует ограничение коллайдеров и ресурсов. Ручная проверка браузера: захват курсора, Escape/возврат, потеря фокуса, HUD и изменение размера окна.

Физическое тело — вертикальный AABB шириной 0,7 м и высотой 1,8 м, позиция задаёт центр стоп. Мир использует статические AABB и наклонные поверхности пандусов; есть скольжение и приземление на верхние грани, но нет автоматического шага на ступени и динамических тел. В режиме паузы симуляция остановлена. Модели, текстуры и звуки можно размещать в `public/assets/`.
